## 1. 서비스 한 줄 정의

가상 보험사 **가온생명** AX팀이 **설계사·창구(고객센터) 직원·본사 법무팀**을 위해 만든 사내 AI 어시스턴트.
약관·규정 질문엔 **약관명·조항 출처와 함께** 답하고, 지표 질문엔 **정의된 지표로** 계산하며, 보험금 지급 여부 같은 **판단 요구는 거절**하고 담당 부서를 안내한다. 회의록을 올리면 요약·결정사항·액션아이템을 만들고 검색 대상에 편입한다.

### 2-1. 데모 계정 원클릭 체험 (변경)

로그인 화면 버튼 3개:

| 버튼 | 체험하는 것 |
| --- | --- |
| `설계사로 체험` | 약관 검색·출처 확인, 판단 요구 거절, 본인 실적 지표 질문 |
| `본사 법무팀으로 체험` | 아래 "법무팀 추가 기능" |
| `AX 관리자로 체험` | 평가 대시보드, 비용·토큰·로그 (읽기 전용) |

#### 본사 법무팀이면 무엇이 추가되나

설계사는 "약관을 **찾는** 사람", 법무팀은 "약관·규정을 **책임지는** 사람"입니다. 그래서 법무팀은 아래 기능이 더 보입니다.

| 추가 기능 | 내용 | 커리큘럼 연결 |
| --- | --- | --- |
| **판단 문의함** | 설계사·창구 직원의 질문이 "판단 요구"로 거절되면, 질문자가 `법무팀에 문의` 버튼으로 넘길 수 있음 → 법무팀 문의함에 쌓이고 답변 등록 | 거절 경로의 "담당 부서 안내"를 실제 흐름으로 완성 |
| **개정 영향 분석** | 개정안 업로드 시 "바뀐 조항을 근거로 인용했던 과거 답변 N건" 목록 → 재안내 필요 여부 검토 | 리스크 레지스터 "약관 개정 반영 지연" 대응 |
| **신구대비표 검토** | 자동 생성된 신구대비표(§5 F2)를 확인하고 `검토 완료` 표시 | 데이터 버전 관리 |
| **👎 피드백 검토** | "답이 틀림·출처 틀림·버전 틀림" 피드백을 받아 정답 기록 → 골든셋 후보로 승격 | 골든셋 보강 루프(운영 계획) |
| **전체 문서 검색 범위** | 팀 한정 문서까지 전부 검색 | 권한 매트릭스 |

> 화면 위치: 사이드바 1행은 3개로 고정이므로, 법무팀·관리자 기능은 **사이드바 하단 프로필 메뉴**에서 열립니다(§4-2).

### 3-1. 배포 — 가장 유리한 조합

| 구성 | 선택 | 이유 |
| --- | --- | --- |
| 프론트 | **Vercel (무료)** | Next.js 제작사, 배포 가장 간단 |
| AI 백엔드 | **Hugging Face Spaces (Docker, 무료 CPU)** | 무료 중 메모리가 가장 넉넉함(16GB급) → bge-m3·Docling·OCR이 돌아감. Render 무료(512MB)는 부족, Fly.io는 무료 플랜 없음 |
| DB·인증·파일 | **Supabase (무료)** | |

알아둘 제약 (리스크 레지스터에 기록):
- HF Spaces 무료는 일정 시간 미사용 시 잠듦 → 첫 요청이 느림(콜드 스타트). 면접 전날 미리 깨워두기
- Supabase 무료는 7일 미사용 시 일시정지 → 주 1회 핑
- Gemini 무료 티어는 분당·일일 호출 한도가 있음 → 골든셋 평가 반복 실행 시 속도 조절 필요. 무료 티어 입력은 모델 개선에 쓰일 수 있으므로 **실제 개인정보·실제 사내 문서를 넣지 않음** (가상 데이터만 사용하는 이유이기도 함)

> ADR 후보: ① Streamlit → Next.js ② Chroma → pgvector ③ 무료 배포 조합 선택

## 5. 기능 구성

### F1. 검색 (약관·규정 RAG + 지표 GenBI, 라우터 자동 분기)

- 질문 → 라우터(§5-2) → 약관·규정 RAG / GenBI / 거절
- 약관·규정 답변은 **약관명 + 조·항 + 버전**을 반드시 표시, 근거 조문이 없으면 답하지 않음
- 판단 요구 → 거절 + 근거 조문만 안내 + `법무팀에 문의` 버튼
- 검색 범위는 로그인 사용자 권한 내 문서만

#### F1-1. 출처 — 클릭하면 원문이 열림 ⭐

```
답변: 비급여 도수치료는 연간 최대 50회까지 보장되며 …
출처: [실손의료보험 표준약관 · 제4조(보상하는 손해) ②항 · 2026.04 개정]  ← 클릭
         ↓
우측 원문 뷰어 열림 → 해당 문서를 그 조항 위치로 스크롤 + 노란 하이라이트
         ↓
[새 탭에서 열기] → /documents/{id}#제4조-2항 (전체 문서, 공유 가능한 링크)
```

- 이를 위해 파싱 단계에서 청크마다 **문서 ID · 관/조/항 번호 · 페이지 · 원문 위치(오프셋)**를 저장
- 출처 칩 hover 시 해당 조문 첫 2줄 미리보기
- 원문 뷰어는 파싱된 마크다운 렌더링(조항 앵커 이동) + 원본 PDF 다운로드 버튼
- 출처가 만료된(구버전) 조항이면 칩에 `구버전` 경고 배지

#### F1-2. 답변 피드백 ⭐

- 답변마다 👍 / 👎
- 👎 클릭 시 사유 선택(복수): `답이 틀림` `출처가 틀림` `약관 버전이 틀림` `거절하지 말았어야 함` `거절했어야 함` `기타` + 자유 입력
- 저장: 질문·답변·출처·사유·트레이스 ID → 법무팀 "피드백 검토" + 관리자 로그에 표시
- 법무팀이 정답을 기록하면 **골든셋 후보**로 승격 → 다음 평가 실행에 포함 (운영 루프)

### F2. 파일 업로드 (데이터 넣기)

- 공개 범위: **전체 공개 / 팀 공개** (업로더 소속 팀만)
- 업로드는 **모든 역할 가능** (데모 제외)
- 메타데이터: 문서 종류(법규·약관·분쟁사례·사내 문서·회의록), 상품/담보명, 적용 시작일, 공개 범위
- 흐름 (승인은 사람 대신 **파서가 자동 판정**):

```
파일 선택(≤10MB) → 메타데이터 입력 → [자동] 파싱 → [자동] 한글 인식률 계산
   ├ ≥ 90%  → ✅ 자동 승인 → 개인정보 마스킹 → 조·항 청킹 → 임베딩 → 검색 반영
   ├ 70~90% → ⚠️ 보류: 파싱 미리보기를 업로더에게 보여주고 "그래도 등록" / "취소"
   └ < 70%  → ❌ 반려: 사유 표시 (예: 스캔 품질 낮음, 글꼴 인코딩 깨짐)
→ 같은 문서의 이전 버전이 있으면 신구대비표 자동 생성 (F2-2)
```

#### F2-1. 자체 파서 (새로 만듦)

| 항목 | 내용 |
| --- | --- |
| 지원 형식 | PDF(텍스트·스캔), HWP/HWPX, DOCX, TXT/MD |
| 제한 | **파일당 10MB** (OCR 비용 때문), 페이지 수 상한 별도 검토(예: 150p) |
| 처리 | ① 형식 판별 → ② 텍스트 추출(PDF는 Docling, HWP는 HWP 파서) → ③ 텍스트가 거의 없거나 깨지면 **OCR(한국어)로 재시도** → ④ 관·조·항 구조 인식 → ⑤ 표(보장 한도표) 보존 → ⑥ 품질 점수 산출 |
| 비동기 | 업로드 후 작업 큐에서 실행, 화면엔 진행 상태(`파싱 중 → 품질 검사 → 임베딩 → 완료`) |
| 산출물 | 조·항 단위 청크 JSON + 파싱 리포트(인식률, 깨진 구간, 표 개수) |

**"한글 인식률" 정의 (직접 작성 대상)**

인식률이 무엇인지 먼저 정의해야 90% 기준이 의미를 가집니다. 제안:

```
한글 인식률 = 정상 한글 어절 수 / 전체 한글(으로 보여야 할) 어절 수
  - 깨진 문자: U+FFFD(�), 사용자 정의 영역 문자, 의미 없는 기호 반복 → 비정상
  - 정상 어절: 형태소 분석기(Kiwi)가 알 수 없는 형태소(UN) 없이 분석한 어절
  - OCR을 거친 경우: OCR 신뢰도 평균과 위 값 중 낮은 쪽 사용
```

> 실제 사례: 이번에 받은 제안서 PDF는 텍스트를 뽑으면 글꼴 인코딩 때문에 `�ýý�`처럼 전부 깨집니다. 이 파서는 이런 파일을 **반려하거나 OCR로 재시도**해야 합니다. 케이스 스터디 4장 "데이터와 파싱"의 좋은 예시이며, 검증용 테스트 파일 세트(정상 PDF·스캔 PDF·인코딩 깨진 PDF·HWP)를 만들어 **기준 90%가 적절한지 실험**합니다.

### 5-1. GenBI — 설계사·창구 직원이 쓸 만한 지표

지표 질문은 검색창에서 그대로 묻습니다(라우터가 자동 분기). 권한에 따라 범위가 다릅니다(설계사=본인, 팀원=소속 팀, 법무·관리자=전사).

### 5-2. 라우터란? (다시 설명)

**한 줄로:** 검색창에 들어온 질문을 보고 **"이건 어느 창구로 보낼까"를 정하는 접수 담당자**입니다.

보험사 지점 접수 창구를 떠올리면 쉽습니다. 고객이 오면 접수 직원이 "약관 문의시면 상담 창구로, 실적·통계면 영업지원으로, 보험금 지급 판단이면 심사팀에 정식 접수하세요"라고 안내하죠. 라우터가 이 역할을 합니다. 덕분에 사이드바에 "지표 메뉴"를 따로 두지 않고 **검색창 하나**로 다 받을 수 있습니다.

```
            질문 입력
               │
        ① 의도 분류 (LLM + 규칙)
     ┌─────────┼─────────────┐
     ▼         ▼             ▼
 약관·규정    지표 질문      판단 요구·범위 밖
  (RAG)      (GenBI)        (거절)
 문서 검색   지표·차원 선택   "판단은 할 수 없어요"
 → 답변 생성  → SQL 템플릿    + 근거 조문 안내
              → 숫자 계산    + 법무팀 문의 버튼
     └─────────┼─────────────┘
               ▼
        ② 답변 검증
   근거 조문이 없거나 판단성 답이면 → 거절로 전환
               ▼
            사용자에게
```

| 질문 예시 | 라우터 판단 | 결과 |
| --- | --- | --- |
| "실손에서 도수치료 보장돼?" | 약관·규정 | 조문 근거 답변 + 출처 |
| "내 13회차 유지율 알려줘" | 지표 | 정의된 지표로 계산한 숫자 |
| "이 고객 보험금 받을 수 있어?" | 판단 요구 | 거절 + 관련 조문 + 법무팀 문의 |
| "오늘 점심 뭐 먹지?" | 범위 밖 | 정중히 거절 |

- 라우터가 틀리면 전체가 틀립니다 → 골든셋에 **라우팅 정답 칼럼**을 넣어 정확도를 따로 측정
- 의도 분류 프롬프트와 분기 조건은 **직접 작성 대상** (커리큘럼 7주차)

- 산출물: 규제 체크리스트(7주차)에 "고지 위치·문구·근거" 표로 그대로 들어감

**① 평가 대시보드**

## 9. 3분 데모 영상 동선 (초안)

1. 로그인 화면 → `설계사로 체험` (AI 고지 동의 모달)
2. "실비로 도수치료 몇 번까지 돼?" → 답변 + 출처 칩 클릭 → 원문 조항 하이라이트
3. "이 고객 보험금 받을 수 있어?" → 거절 + `법무팀에 문의`
4. "내 13회차 유지율은?" → 지표 경로 배지 + 숫자
5. `본사 법무팀으로 체험` → 개정안 업로드 → 파서 판정 ✅ → 신구대비표 → 같은 질문에 바뀐 답 → 개정 영향 12건
6. 회의록 → "한도 줄인 이유?" → 회의록 + 약관 함께 근거
7. `AX 관리자로 체험` → 평가 대시보드 전후 수치, 비용·토큰 로그
