# 문제 정의서

> 1–2페이지. 기획자의 언어로, 기술 해결책보다 문제를 먼저.

## 한 줄 문제
설계사 영업 시와 고객센터에서 상담 응대 시에 약관을 정확히 말해 줘야 하는 경우, 관련된 약관 부분을 부정확하게 설명할 수 있고 기억에 의존하여 최신화된 약관을 인지하지 못할 수 있음. 또한 약관을 찾기까지 대면 상담의 경우 시간이 오래 걸림.

## 누가
- 설계사, 고객센터 응대

## 어떤 상황에서
- 고객 대면 시 / 고객센터 채팅 문의 시

## 지금 어떻게 해결하나
- 추정: 기억에 의존하거나 현장에서 약관을 찾아서 알려 줌 / 사내 데이터베이스를 참조

## 무엇이 불편한가 (가능하면 시간·횟수·오류로)
- 불확실할 수 있고, 시간이 오래 걸림.
- 시간: LLM에 넣는 시간과 직접 찾는 시간은 많은 차이가 나겠지만, 재는 것은 실제로 일부 배포 후에 단축 시간과 설문을 통해 봐야 함. 고객센터 쪽은 좀 더 확실히 데이터화할 수 있을 것 같음.
- 부정확하게 설명하는 빈도: 알 수 없음.
- 약관이 최신화되는 빈도: 알 수 없음. 별도의 검색 필요.

## 왜 지금인가
- 금융 기업에서도 LLM의 사용 환경이 점점 개선되고 있기 때문에, 도입하기 좋은 시기.
- 추정: 약관 개정이 잦아지는지는 모름.

## 성공하면 무엇이 달라지나
- 응대 시간 감축 및 정확한 정보 제공을 통한 만족도 상승.
- 고객센터를 기준으로 하면, 고객별 대화 개수, 시간, 재문의율, 만족도로 수치화할 수 있음.

## 범위 밖 (이 프로젝트가 하지 않는 것)
- 보험금 지급 여부 판단
- 민감성 내용이 들어간 내용에 대한 판단(동의 필요)
  - 상담을 시작할 때 개인정보 수집에 민감정보를 함께 처리할 수 있다고 동의서를 받아야 할 것 같음.
