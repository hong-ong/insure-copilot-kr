작성일: 2026-10-06
다음 주제: ③ 임베딩 → ④ temperature → ⑤ 할루시네이션

## ① 토큰

### 핵심 개념
- **정의**: LLM이 텍스트를 읽고 쓰는 최소 단위. 텍스트 → 토큰 조각 → 토큰 ID(숫자) → 모델.
- **왜 서브워드인가**
  - 글자 단위: 모르는 단어는 없지만 문장이 너무 길어짐 → 계산량 증가
  - 단어 단위: 어휘가 폭발하고, 사전에 없는 단어(신조어·줄임말·오타)는 처리 불가(OOV)
  - 서브워드: 자주 나오는 조각은 하나로, 드문 단어는 조각의 조합으로 → 절충안
- **BPE**: 가장 작은 단위에서 시작해 가장 자주 붙어 나오는 쌍을 반복 병합. 토크나이저는 **모델 학습 전에** 빈도 통계로 따로 만들어지고, 모델마다 고정됨.
- **바이트 단위 BPE**: 한글 1자 = UTF-8 3바이트 → 드문 글자는 토큰 2~3개로 쪼개질 수 있음.
- **한국어**: 같은 내용도 영어보다 토큰이 많이 나오는 경우가 흔함. 모델마다 차이 큼 → **어림값 외우지 말고 쓰는 모델로 직접 측정.**
- **생성 방식**: LLM은 다음 토큰을 하나씩 예측해 이어 붙임 → temperature, 할루시네이션과 연결.

### 현직에서의 쓰임
| 영역 | 내용 |
| --- | --- |
| 비용 | 입력 토큰 × 입력 단가 + 출력 토큰 × 출력 단가 (출력 단가가 보통 몇 배 비쌈) |
| 지연 | TTFT(첫 토큰까지 시간, 입력 길이 영향), tokens/sec. 응답 시간은 대체로 출력 토큰 수에 비례 |
| 길이 제한 | max_tokens(출력 상한), 걸리면 `finish_reason=length`로 잘림. 임베딩 모델도 입력 한도 있음 |
| 사용량 한도 | RPM, **TPM**(분당 토큰). 골든셋 일괄 실행 시 재시도·대기 로직 필요 |
| 프롬프트 캐싱 | 고정된 앞부분은 캐시 할인 → 고정 내용은 앞, 바뀌는 내용(검색 결과·질문)은 뒤 |
| 기획 문서 | PRD 비기능 요구사항(질의당 토큰·비용), 가드레일 지표, 비용 폭주 알림 기준 |

### 질의당 비용 예시 (가정 단가: 입력 $0.30/1M, 출력 $2.50/1M)
| 구성 | 토큰 | 비중 |
| --- | --- | --- |
| 시스템 프롬프트 | 800 | 10% |
| 검색 청크 5개 | 3,000 | 37% |
| 질문 | 50 | 1% |
| 출력 | 500 | **52%** |

→ 구성에 따라 출력이 클 수도, 입력이 클 수도 있음. **비중부터 계산하고 큰 쪽부터 줄인다.**

### 비용을 줄일 때 같이 볼 품질 지표
| 줄이는 것 | 방법 | 같이 볼 지표 |
| --- | --- | --- |
| 검색 청크 | top-k 축소, 청크 크기 축소, 리랭커 | Recall@k, 정답률 |
| 출력 | 답변 형식 지정 + max_tokens는 안전장치 | 정답률, 출처 누락률, 잘림 비율 |
| 시스템 프롬프트 | 캐싱, 규칙 정리 | 거절 정확도 |

### 면접 모범 답안 요지
1. **왜 서브워드인가** → 글자/단어 단위의 트레이드오프 → 서브워드는 빈도 기반 절충, 어휘 크기 적정 + 모든 단어 표현 가능.
2. **단가는 B가 싼데 비용이 더 나왔다** → "토큰 수 × 단가"로 봐야 함. ① 토크나이저 차이(B가 더 많이 쪼갬) ② 답변이 더 김 ③ 추론 모델의 보이지 않는 추론 토큰 ④ 캐싱 할인 미적용. → **골든셋으로 실측 비교.**
3. **질의당 비용 줄이기** → 구성별 비중 계산 → 큰 쪽부터 줄이되 품질 지표를 함께 보고, 판정 기준을 정해 골든셋 전후 비교.

### 내가 틀렸던 포인트
- ❌ "단어 단위면 토큰이 많이 소비된다" → 반대. 토큰이 많아지는 건 **글자** 단위. 단어 단위의 문제는 어휘 폭발과 OOV.
- ❌ "LLM이 자체적으로 단어를 설정한다" → 토크나이저는 학습 **전에** 별도로 만들어져 고정됨.
- ❌ "토큰 오거나이저", "설정값" → **토크나이저**, 모델마다 고정된 것.
- ❌ "B가 약관에 더 알맞다" → 결론 반대. 비용이 더 나왔으면 B가 **덜** 효율적.
- ❌ "출력 토큰의 맥스 컨텍스트" → **max_tokens**. 컨텍스트 윈도와 다른 개념.
- ⚠️ 원인을 하나만 댐 → 2~3개 대기.

## ② 컨텍스트 윈도

### 핵심 개념
- **정의**: 한 번의 호출에서 볼 수 있는 토큰 최대치. **입력 + 출력 합산** 상한. (비유: 책상 크기)
- **윈도 안의 구성**: 시스템 프롬프트 / 도구 정의 / 대화 이력 / 검색 결과 / 현재 질문 / 출력 공간 → 이를 나누는 게 **컨텍스트 예산**.
- **한계의 이유**: 어텐션 계산량이 길이의 제곱에 비례, KV 캐시 메모리, 학습 길이.
- **"넣을 수 있다" ≠ "잘 쓴다"**
  - **Lost in the Middle**: 앞·끝 정보는 잘 쓰고 중간은 놓침 (Liu et al., 2023)
  - **유효 컨텍스트 < 광고된 컨텍스트**, 컨텍스트 로트
  - 비슷한 문서끼리 섞임 → 실손 세대별 **약관 버전 혼동**
- **모델은 기억이 없다(stateless)**: 앱이 매 턴 이전 대화 전체를 다시 보냄 → 턴마다 입력 증가, 누적 비용은 턴 수보다 훨씬 빠르게(대략 제곱에 가깝게) 증가.
- **넘치면**: 에러, 또는 프레임워크가 **조용히 앞부분을 잘라냄** → 시스템 프롬프트(안전 규칙)가 사라질 위험.

### RAG vs 통째로 넣기
| 기준 | 통째로 넣기 | RAG |
| --- | --- | --- |
| 문서 양 | 소수 문서 | 수백~수만 문서 |
| 비용·지연 | 매 호출 전체 과금, 느림 | 검색 청크만, 빠름 |
| 전체 맥락(요약·비교) | 유리 | 불리 |
| 출처 검증 | 어려움 | 청크 ID로 코드 검증 가능 |
| 권한 | 넣기 전 별도 필터 | 검색 단계 메타데이터 필터 |
| 버전 혼동 | 섞일 위험 | 버전 메타데이터로 분리 |

### 현직에서의 쓰임
- **컨텍스트 예산표** (예: 시스템 1,000 / 이력 2,000 / 청크 4,000 / 질문 200 / 출력 800 = 8,000). 윈도가 커도 의도적으로 작게 운영.
- **배치 순서**: 고정 지시는 앞(캐싱), 중요 청크는 앞이나 끝, 긴 문서는 질문을 뒤에, 청크마다 문서명·조문·버전 태그.
- **넘침 방어**: 전송 전 토큰 계산, 줄이는 순서 규칙(대화 이력 → 검색 청크), 시스템 프롬프트는 **고정 영역**.
- **모니터링**: 질의당 입력 토큰 평균·p95.
- **모델 선택**: 윈도 크기는 "충분한가"만 확인. 그다음은 품질·비용·속도.
- **대화 관리**: 슬라이딩 윈도(최근 N턴), 요약, 매 질문마다 재검색.

### 면접 모범 답안 요지
1. **100만 토큰 모델인데 왜 RAG?** → ① **품질**(Lost in the Middle, 버전 혼동) ② 출처 검증 ③ 권한 필터 ④ 비용·지연(캐싱으로 비용은 줄어도 품질 문제는 남음) → "1주차에 베이스라인을 직접 측정해 비교했다"로 마무리.
2. **20턴째 판단 요구에 답해 버림** → **트레이스부터 확인** → 시스템 프롬프트가 빠졌으면: 고정 영역화 + 이력 트리밍/요약 → 들어가 있었으면: 지시 희석 또는 점진적 유도 → 핵심 규칙 재주입 + **출력 전 검증 단계** → **다턴 케이스를 골든셋에 추가해 회귀 테스트.**
3. **대화가 길수록 느리고 비싼 이유** → 모델은 기억이 없고 **앱이** 이전 대화를 매번 다시 보냄 → 입력 증가 → 과금 증가 + TTFT 증가, 누적 비용은 턴 수보다 빠르게 증가 → 대응: 최근 N턴 유지, 요약, 재검색.

### 내가 틀렸던 포인트
- ⚠️ RAG 이유에서 **품질**을 빠뜨림 → AI 기획자 답변의 1순위.
- ❌ "컨텍스트 윈도엔 메타데이터가 없다" → 태그는 넣을 수 있음. 진짜 차이는 **검색된 청크 ID로 인용을 코드 검증** 가능한 것.
- ⚠️ "천문학적 비용" 과장 → 캐싱 반박에 대비. 숫자로 말하기.
- ❌ "앞순위에 배치하면 안 잘린다" → 보통 **앞에서부터** 잘림. 보호는 위치가 아니라 **고정 영역 규칙**. 앞에 두는 이유는 캐싱.
- ⚠️ 원인을 하나만 댐(잘림) → 희석, 점진적 유도도 있음. **진단(트레이스 확인)** 단계 누락.
- ❌ "모델이 이전 대화를 가져온다" → **앱(서버)이 다시 보낸다.** 모델은 받기만 함.
