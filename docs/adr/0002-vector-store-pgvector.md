# ADR-0002: 벡터 저장소를 Chroma 대신 Supabase pgvector로 한다

- 날짜: 2026-10-19
- 상태: 채택

## 맥락
문서마다 공개 범위(전체 / 팀)가 있고, 검색 결과는 질문자 권한 안에서만 나와야 한다.
약관은 버전(적용 기간)이 있어 "현재 유효한 버전"만 고르는 필터도 필요하다.

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| A. Chroma | 커리큘럼 그대로, 로컬에서 간단 | 권한 필터를 앱 코드에서 따로 구현, 사용자·문서 DB와 분리되어 동기화 필요 |
| B. Supabase pgvector | 문서·권한·대화 기록과 같은 DB, 검색 함수에 RLS가 그대로 적용 | Postgres SQL 학습 필요, 무료 티어 용량(500MB) 제한 |

## 결정
B. `match_chunks` 함수를 `security invoker`로 만들어, 로그인 사용자의 권한(RLS)으로 검색한다.
"권한 밖 문서가 검색 결과에 안 나온다"를 앱 코드가 아니라 DB 정책으로 보장한다.

## 결과와 트레이드오프
- 7주차 권한 테스트 10문항을 RLS 정책 검증으로 바로 쓸 수 있음
- 5주차 BM25·하이브리드 실험은 Python 쪽(Kiwi + rank-bm25)에서 후보를 합치는 방식으로 진행
- 다시 검토할 조건: 청크가 수십만 개로 늘어 무료 티어를 넘을 때
