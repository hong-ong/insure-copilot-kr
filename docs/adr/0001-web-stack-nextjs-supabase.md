# ADR-0001: 화면을 Streamlit 대신 Next.js + Supabase로 만든다

- 날짜: 2026-10-19
- 상태: 채택

## 맥락
커리큘럼은 화면을 Streamlit으로 잡았다. 그런데 10 → 1 방식으로 바꾸면서 요구사항이 늘었다.
- 누구나 접속하는 공개 웹사이트이되, 가입(이메일·Google·Kakao)한 사람만 사용
- ChatGPT형 레이아웃: 왼쪽 사이드바(기능 3개 + 최근 검색), 가운데 대화, 오른쪽 원문 뷰어
- 역할(설계사·법무팀·AX 관리자)별로 보이는 문서·지표·화면이 달라야 함
- 채용 담당자가 가입 없이 바로 체험하는 데모 계정

## 선택지
| 안 | 장점 | 단점 |
| --- | --- | --- |
| A. Streamlit | Python 하나로 끝, 커리큘럼 그대로 | 사이드바·우측 패널·라우팅 등 레이아웃 자유도 낮음, OAuth·세션 관리가 번거로움, "사내 도구 시제품" 인상 |
| B. Next.js + Supabase | 업계 표준 UX, Supabase Auth가 이메일·OAuth·익명 로그인 제공, RLS로 권한을 DB에서 강제 | 언어가 둘(TS + Python), 배포 대상이 둘 |

## 결정
B. 화면과 인증은 Next.js + Supabase, AI 처리(파싱·검색·생성·GenBI)는 Python FastAPI로 분리한다.
LiteLLM·평가·실험 등 커리큘럼의 핵심 학습은 모두 Python 쪽에 남는다.

## 결과와 트레이드오프
- 얻은 것: 실제 서비스 수준 UX, 권한 정책을 RLS 정책 SQL로 보여줄 수 있음
- 포기한 것: 구조가 복잡해짐(프론트·백엔드·DB 세 곳). 화면 코드는 학습 대상에서 제외(TS 함수 docstring 규칙 완화)
- 다시 검토할 조건: 배포·운영 부담이 학습 시간을 잠식할 때
