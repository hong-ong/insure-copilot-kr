# ADR-0004: 가온생명 RAG의 약관 원문을 교보생명 공시 약관으로 교체

- 날짜: 2026-11-17
- 상태: 채택 (실행은 0부 준비 안에서)

## 맥락
- 서비스 DB에는 직접 만든 가상 약관(가온 실손 특약 2025.07·2026.04 판)과 사내 문서·회의록만 있다(문서 7개 · 청크 85개).
- README·학습 로그는 "약관은 교보생명 공시 약관 기준"으로 바뀌었지만, 교보 약관 9개 판(`data/manifest.csv`)은 아직 파싱·적재하지 않았다.
- 데모 질문·영업 가이드·회의록·업로드 데모가 가상 개정(2025.07 → 2026.04 도수치료 한도)에 묶여 있다.
- 교재 실습 원문은 표준약관(`silson_standard.pdf`)으로 잡혀 있어, 평가 대상과 서비스 원문이 다르다.

## 선택지
| 결정 항목 | 안 | 장점 | 단점 |
| --- | --- | --- | --- |
| 가상 약관 | a. 교보 약관으로 완전 교체, 데모 자료도 교보 약관 내용에 맞춰 다시 씀 | 평가 대상 = 서비스 원문 | 데모 시나리오를 다시 짜야 함 |
| | b. 교보 약관 추가, 가상 약관은 데모용으로 남김 | 작업량 적음 | 원문이 두 종류로 섞임 |
| 화면 이름 | A. 교보 상품명 그대로 | 원문과 같음 | 가온 브랜드와 교보 상품명이 섞임 |
| | B. "가온 ○○보험 (교보생명 공시 약관 기반)"으로 표시, 출처에 원래 이름 | 브랜드 일관, 출처 투명 | 표시명 매핑 관리 필요 |
| 교재 실습 원문 | 표준약관 / 교보 약관 | — | — |

## 결정
1. **a** — 교보 약관 9개 판으로 완전 교체한다. 가상 약관 2개 판은 내리고, 데모 질문·영업 가이드·회의록·업로드 데모를 교보 약관 내용에 맞춰 다시 쓴다. 사내 문서·실적 데이터(GenBI 마트)는 가상으로 유지한다.
2. **B** — 화면에는 가온 표시명을 쓰고, 출처에는 교보생명 원래 상품명·판·파일명을 함께 적는다.
   표시명 규칙: 상품명의 "교보" → "가온" + " (교보생명 공시 약관 기반)" (`data/manifest.csv`의 `display_name`).
   **약관 본문은 원문 그대로 둔다** — 본문의 "교보생명" 문구를 바꾸지 않는다. 인용문이 원문과 같아야 근거를 확인할 수 있다.
3. **교재 실습 원문 = 교보 약관** (`data/manifest.csv`의 9개 판). 골든셋·평가도 같은 원문으로 한다.
4. **0부 준비**에 포함한다 — 2026-11-11 기능 동결의 예외가 아니라, 평가 전에 원문을 맞추는 준비 작업으로 본다.

## 결과와 트레이드오프
- 얻은 것: 평가(골든셋) 원문과 서비스 원문이 같아져 수치가 의미를 갖는다. 실제 약관의 판별 차이로 버전 질의를 검증할 수 있다.
- 포기한 것: 가상 개정 시나리오. 암보험 판당 약 3,700쪽이라 적재·임베딩 비용과 시간이 크다.
- 제약: 파일이 1.4~40.8MB라 화면 업로드(10MB, Vercel 4.5MB)로는 못 넣는다 → 로컬 적재 스크립트로 넣는다.
- 다시 검토할 조건: 임베딩 무료 한도나 DB 용량을 넘으면 범위(특약 포함 여부·판 수)를 줄인다.
